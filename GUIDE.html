하루를 이렇게 보내세요

  1. 읽기대시보드의 학습 노트(study-notes/)에서 오늘 주제의 개념, 예시, 문서 찾는 법을 봅니다. 30~40분.
  2. 문서 위치 익히기시험 중에 열 공식 페이지를 직접 열고, 무엇을 검색할지 정합니다.
  3. 풀기오늘 배정된 문제를 시뮬레이터에서 풉니다. 풀이는 보지 않습니다.
  4. 채점exam check로 점수를 보고, 틀린 체크를 확인합니다.
  5. 풀이 비교solution.md를 열어 더 빠른 방법이 있었는지 봅니다.

문제당 목표는 약 6분입니다(2시간, 15~20문제). 처음에는 시간을 재지 말고 정확하게 풀고, 11일차부터 시간을 제한하세요. 계획을 2주에 못 끝내면 같은 순서로 이어가면 됩니다.

학습 대시보드

오늘 일차의 개념과 문제를 클릭으로 열고, 그 자리에서 시뮬레이터를 시작하는 화면입니다. 내 컴퓨터에서만 열립니다. 이 페이지는 서버에 올라가 있어서 시뮬레이터를 직접 실행할 수 없기 때문에, 대시보드는 따로 실행해야 합니다.

cd simulator
bin/web # 토큰이 붙은 주소를 출력하고 브라우저를 엽니다 (기본 127.0.0.1:8765)
bin/web --check # 서버 없이 파싱 결과만 확인: 14일, 87개 개념, 110문제
bin/web --dry-run # 버튼이 실행할 명령만 보여줌
brew install ttyd # 브라우저 안 터미널을 쓰려면 (직접 설치)

화면 구성

  • 홈: 14일 계획. 일차마다 연관 개념과 문제 칩(배점, 난이도, 충실도, 충돌 경고, 검증 상태)
  • 학습 노트: 그날 하위 역량마다 study-notes/의 상세 노트(개념 설명, 예시, 공식 문서에서 찾는 법, 흔한 실수, 빠르게 푸는 순서)
  • 일차 카드: 위쪽 칩은 그날 계획에 배정된 문제만입니다. 같은 개념의 다른 날 문제는 접힌 ‘추가 연습’ 안에 있고 건너뛰어도 됩니다
  • 개념 목록: 87개 개념을 영역·충실도로 걸러서 보기
  • 문제 페이지: 시작, 터미널, 채점, 초기화, 풀이 보기, ‘처음부터 다시 풀기 / 다른 문제에 영향을 줄 때’ 안내

확인한 것과 못 한 것

  • 실제 클러스터에서 확인: q01 시작(시드), 채점(0/13), 초기화, 풀이 잠금(채점 전 403, 포기 체크 후 열림)
  • 토큰 없는 요청, 다른 출처의 요청은 403으로 막힘
  • 브라우저 안 터미널(ttyd): 설치 후 직접 확인했습니다. 시작하면 candidate@cka-term 셸에 WebSocket으로 접속되어 명령이 실행되고, 중지도 동작합니다. ttyd가 없으면 bin/sim term 안내가 나옵니다
  • 화면 모양(라이트·다크)과 버튼 클릭은 브라우저에서 직접 보지 않았습니다

대시보드가 문제를 시작하면 state/share/session.json을 쓰므로, 터미널에서 bin/exam start로 모의시험을 하는 중에는 같이 쓰지 마세요.

시뮬레이터 사용법

Docker Desktop에 메모리를 6GB 이상(권장 8GB) 주세요. 처음 켤 때 약 4분 걸리고, 클러스터 두 개가 떠 있으면 메모리를 약 3GB 씁니다.

# 처음 한 번: 환경 켜기
cd simulator
bin/sim up # 이미지, 클러스터(k8s, ek8s), 애드온, 시험 터미널
bin/sim doctor # 상태 점검
# 한 문제씩 연습 (시간 제한 없음)
bin/exam practice q01 # 시작 전에 직전 세션이 바꿔 둔 것(노드 label/taint, kubelet 수정 등)을 먼저 되돌림
bin/exam cleanup # 문제를 시작하지 않고 직전 세션의 변경만 되돌리기
bin/sim term # 시험 터미널에 접속 (tmux)
# 시험 터미널 안에서
exam q # 문제 보기 (컨텍스트, 네임스페이스, 배점 표시)
exam check # 채점
exam reset # 이 문제만 처음 상태로 (같은 문제를 처음부터 다시 풀 때)
ssh k8s-cp # 노드 작업은 ssh 후 sudo -i
# 모의시험: 문제은행에서 16문항 세트를 만들어 2시간 타이머로
bin/mkset my-set # 충돌하는 문제는 한 세트에 넣지 않고, q18·q80은 항상 마지막
bin/exam start mock-a # 또는 my-set. 연습 모드는 --practice
exam next / prev / list / flag / timer / score / end
# 끝나면
bin/sim down all # 시뮬레이터 컨테이너만 삭제

실제 시험과 같게 만든 것

  • 문제마다 컨텍스트가 지정됨: k8s, mk8s, wk8s, ek8s
  • 노드는 ssh 후 sudo -i
  • 터미널에서 인터넷이 막혀 있음(공식 문서는 본인 브라우저로 보세요)
  • 부분 점수, 합격선 66%
  • exam check는 끝나기 전에 상세를 숨김(--practice면 보임)

실제 시험과 다른 것

  • kind 위에서 돌아가서 kubeadm 업그레이드·조인, CNI 설치 일부는 근사치입니다
  • 컨텍스트 4개 중 mk8s·wk8s는 같은 클러스터의 별칭입니다
  • kubeadm 업그레이드 연습(q19)은 bin/sim up ik8s로 별도 클러스터가 필요합니다
  • 실제 시험의 컨텍스트 수와 화면 구성은 공식 자료에 없어 확인되지 않았습니다

충실도 표시

kind에서 실제 시험과 얼마나 같게 재현되는지를 문제마다 표시했습니다.

high

실제 동작을 채점합니다. 시험과 거의 같은 경험입니다.

partial

일부는 파일이나 API 오브젝트만 확인합니다. 예: LoadBalancer, PVC 확장(local-path는 실제로 늘리지 않음).

low

개념 연습용입니다. 예: VPA(kind에 컴포넌트 없음), 노드 사전 준비. 점수보다 절차를 익히는 용도입니다.

COVERAGE.md 기준으로, 충실도가 높은 문제가 하나도 없는 개념은 11개입니다: PVC 확장, VPA, 노드 사전 준비, kubeadm init, kubeadm upgrade, HA 토폴로지, CNI 설치, CSI, CRI/RuntimeClass, LoadBalancer, IngressClass. 이 개념들은 실제 시험 전에 공식 문서의 절차를 따로 읽어 두세요.
