## Procedure used (real runner path)
1. `bin/exam start --practice --duration 0m <qid...>` seeds every question in the batch through `seed_one` (logs in `state/logs/setup-<id>.log`).
   Then `setup.sh` is run a second time to check that it is idempotent (rc must be 0, and the state must stay broken/seeded).
2. Grade the untouched state with `grade.sh`. The environment is the same as `exam check`: QID/QDIR/SIM_ROOT/LIB/ADMIN_KUBECONFIG, cwd = the question dir.
3. Run the solution.md commands as `candidate` in exam-term (`docker exec -i -u candidate -w /home/candidate exam-term bash -l < script`).
   Node steps use `ssh <alias> 'sudo -i bash -s'`. A vim edit is replaced by writing the exact YAML from solution.md, or by the equivalent `kubectl patch`/`yq` edit.
4. Grade again, then run `bin/exam reset <n>` (cleanup.sh + default cleanup + re-seed), then grade the reset state (it must score low again).
5. Final cleanup: cleanup.sh + default label cleanup (+ `sim restore-node` for cluster-soft). Then check for leftover objects and run `bin/sim doctor`.

Scores are passed/total points. "untouched" = right after setup, "solution" = after solution.md, "after reset" = after `exam reset`.


Lanes A..I used the direct procedure instead of `bin/exam start`: per question `setup.sh` twice, grade untouched, solution.md as candidate in exam-term, grade, cleanup/reset, setup + grade, final cleanup. Direct call form: `(cd $S/questions/<id> && QID=<qNN> QDIR=$PWD SIM_ROOT=$S LIB=$S/lib ADMIN_KUBECONFIG=$S/state/admin.kubeconfig bash setup.sh)` (same for grade.sh / cleanup.sh).
