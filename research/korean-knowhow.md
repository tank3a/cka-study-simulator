## 3. 시간 관리 전략

### 3-1. 문제당 시간 배분

- S5: 2시간 / 14~17개 과제 = 과제당 약 6분으로 계산. 모든 문제를 시도하라고 권함. 부분 점수가 있다는 점을 근거로 듦.
- S11 (2024): 헷갈리는 문제는 과감히 넘기고 전체를 다 푼 뒤 돌아오기. 뒤쪽 문제가 대체로 간단해서 머리를 식힐 수 있었다고 함. S8(문제 2개 건너뜀)과 같은 방향. **(corroborated: S8, S11)**
- S11 (2024): 1번 Network Policy 문제에서 약 5분을 헤매다 넘겼다는 경험 공유. 문제별 시간 기준은 명시 없음.

### 3-2. 건너뛰기와 재검토

- S8: 문제 2개를 건너뛰었다고 명시. 점수가 기대보다 낮았던 원인은 "실수가 좀 있었기" 때문이라고 함.
- S6: 마지막 문제를 풀지 못한 채 30분이 남자, 그 문제를 포기하고 이미 만든 리소스를 처음부터 다시 검토. 검토 시간을 확보했다는 점이 특징.
- S5: 부분 점수가 있으니 빈 문제를 남기지 말라는 조언.

### 3-3. 명령어와 YAML 작성 방식

- S5: `kubectl`로 뼈대 YAML을 만든 뒤(--dry-run=client -o yaml), 빠진 옵션만 공식 문서에서 찾기. 공식 문서에서 찾기 어려운 항목(예: Gateway TLS)은 미리 검색 키워드를 외우기.
- S10 (2024): 명령형 kubectl을 우선하고, YAML을 처음부터 쓰지 않기. 문서에서 템플릿 복사. vim에서 `%s/old/new`로 이름을 일괄 변경. 시험은 약 1시간 만에 끝났다고 함.
- S8: 시험 환경의 반응 속도가 느리므로 문서 검색을 최소화하고 명령어를 외워 두라는 의견.
- S2: "한 줄 kubectl 명령"을 외우고, 시험 중 YAML을 처음부터 쓰는 시간을 줄이라고 함. **(corroborated: S2, S3, S5, S10 — YAML 작성 시간 부담 언급)**
- S3: YAML 직접 작성이 낯설었고 시간이 부족했다고 함. 공식 문서 검색 속도도 실력이라고 봄.

### 3-4. 시간이 부족했다는 기록

- S3: 시험 중 시간이 부족했고, 조급해하지 말라고 조언. S6: "2시간은 생각보다 넉넉하지 않다"고 함. **(corroborated: S3, S6 — 시간이 빠듯했다는 기록)**

## 4. 터미널 환경 설정

### 4-1. alias, export (2편 이상 확인)

- `alias k=kubectl` (S10, S11; S11은 `alias kd='k describe'`도 추가) **(corroborated, 2024 글 2편)**
- `alias ka=kubectl apply -f`, `alias now=--grace-period=0 --force` (S10). S11은 `export now='--force --grace-period 0'`을 사용.
- `export do="--dry-run=client -o yaml"` 별칭은 S11에서만 확인됨. `--dry-run=client -o yaml`로 YAML 뼈대를 만드는 방식은 S5, S6, S11이 언급. **(corroborated: dry-run 사용 3편, `do` 별칭은 1편)**
- `export now='--force --grace-period 0'` (S11)
- 시험 환경에 k alias와 kubectl 자동완성은 이미 있다는 기록은 검색 요약에만 있고 본문 확인은 못 함.

### 4-2. vim

- S12 (2023): 시험 중 메모장 대신 터미널에서 `vi`를 메모장처럼 사용. 시험 환경은 vi가 vim으로 연결되어 있지만 .vimrc를 읽지 않아 직접 설정해야 한다는 내용은 검색 요약 기반이라 본문 확인은 못 함.
- S10 (2024): vim으로 일괄 치환 (`%s/old/new`). **(corroborated: S10, S12 — 편집기로 vim/vi 사용)**

### 4-3. tmux

- 본문을 읽은 12편 중 tmux를 언급한 글은 없습니다. 검색 요약에서는 "tmux가 미리 설치되어 있다"는 의견과 "GUI 환경에서 여러 창을 쓰므로 tmux가 줄었다"는 의견이 함께 나왔지만 본문으로 확인하지 못했습니다. 따라서 이 항목은 **확인되지 않음**으로 둡니다.

### 4-4. 복사와 붙여넣기 (corroborated, 4편 이상)

- S4 (2025-01): 터미널은 Ctrl+Shift+C / Ctrl+Shift+V. 시험 문제에서 원격 환경으로는 마우스 우클릭이 가장 정확하다고 추천. 문제에 나온 Pod 이름 같은 항목은 클릭하면 바로 복사됨.
- S5 (2026): Ctrl+C/V가 안 되면 Ctrl+Insert, Shift+Insert를 시도. VSCodium에서 먼저 작성해 붙여넣는 방식이 안정적이었다고 함(Windows 11 + Chrome 기준).
- S6 (2025-07): Mac에서 command+c가 아니라 control+c로 동작. 포커스가 브라우저인지 터미널인지에 따라 단축키가 달라짐. 단축키에 익숙하지 않으면 Firefox 개발자 도구가 열리는 등 문제가 생김.
- S11 (2024): 터미널 붙여넣기는 Ctrl+Shift+V. killer.sh에서 미리 익히라고 권함. 코드 블록을 클릭하면 자동 복사됨.
- S12 (2023): 원격 환경 클립보드 패널이 키보드로는 안 되고, 문제 속 이름이나 경로를 클릭하면 복사가 잘 됐다.

- S1 (2025-11-27): 책상, 천장, 바닥, 키보드, 마우스패드, 귀, 손목까지 카메라로 보여줘야 했다고 함. 맥북을 외장 모니터와 함께 클램셸 모드로 사용.
- S11 (2024): 14인치 노트북 사용 규정이 있었고, 모니터를 쓰려면 웹캠이 추가로 필요하다고 함.
- S10 (2024): 감독관이 무선 마우스 동글에 연결된 USB 허브 용도를 물었고, 마우스 연결용이라고 답하니 인정됨.

### 4-6. 시험 시작 전 환경 점검

- S4: 시작 30분 전 입실. 원격 프로그램 설치, 신분증, 책상, 방 검사에 20~30분 소요.
- S8: 환경 점검에 약 20분. 감독관이 CCTV 방향으로 모니터를 돌리지 말라고 요청.
- S1: 환경 점검에 약 40분, 브라우저가 4번 멈춤. 재시작하면 점검을 다시 해야 함. 시험 전에 미리 테스트하라고 권함.
- **(corroborated, 3편 이상: S1, S4, S8)**: 환경 점검 시간을 20~40분으로 예상하고 일찍 접속하기.
- S8: "Take Exam" 버튼이 30분 전에 활성화되는데, HTTP 500 오류가 계속 나서 약 15분 늦게 입실. 브라우저 캐시와 쿠키를 지우니 해결. 지원팀 답변은 시험 종료 후에 옴.

## 6. 함정 (pitfalls)

- **잘못된 노드에서 작업** (S10, 2024): SSH 세션을 끊지 않고 다음 문제를 풀어 다른 노드를 망가뜨림. 점수가 크게 깎였다고 함. 노드마다 별도 콘솔 창을 열라고 권함. S5도 과제마다 SSH 접속 후 종료하고, 올바른 호스트인지 확인하라고 함. **(corroborated, 2편)**
- **컨텍스트 전환 누락** (S11, 2024): 문제마다 `kubectl config use-context`를 빠뜨리지 말라고 강조. S8 등은 각 문제 첫 줄의 클러스터 진입 명령을 그대로 복사해 실행하라고 권함(검색 요약 기반).
- **문제 끝까지 읽기** (S2): "하지 말라는(do-not)" 조건을 놓쳐 실점. **(본문 1편)**
- **리소스를 실수로 삭제** (S3): 삭제 후 다시 만들어야 해서 시간 손실이 큼.
- **네임스페이스 실수**: 본문 기준으로 검증된 기록은 찾지 못했습니다. 위의 use-context 항목이 가장 가까운 근거입니다.
- **Deployment label 변경**: Pod을 내렸다가 다시 띄워야 한다는 점 (S11, 2024).
- **CRD 출력 형식 요구사항 누락**: 요구 형식을 따르지 않으면 감점 (S8).
- **인터넷 끊김** (S2): 첫 시험 중 연결이 끊겨 복구하는 과정에서 일부 문제를 망가뜨림.
- **Gateway TLS 설정 예제는 공식 문서에서 찾기 어렵다** (S5, S8). **(corroborated, 2편)**
- **Kubernetes 공식 문서 버전 차이**: 문서가 버전마다 다르고 예제가 없는 부분이 있음 (S3, S11).
- **killer.sh 난이도**: 실제보다 어려워 멘탈이 흔들린다는 기록 (S7, S9, S10, S11). **(corroborated, 4편)**
- **규정 위반**: 자리를 떠나거나 감독관 허락 없이 다른 사람이 들어오면 실격(S10). 시험 중 외부 사이트는 자동 차단, gedit 미설치, 번역 플러그인은 입력 텍스트만 번역(S12).
- **예약 전 신분증**: 여권을 미리 등록해 두라는 조언(S5).
- **예약 가능 시간**: 오전 시간대만 열리는 날이 있고, 낮 시간은 취소가 나오면 열림(S5).
- **재시험 기회**: 응시권 만료일이 재시험 날짜보다 앞서면 CKS 응시 불가 같은 문제 발생 가능(S5).
- **갱신**: 2년마다 재응시해야 자격이 유지됨(S7).

## 10. 2025 이후 글 기준 합의 사항 (15줄 요약)

1. 기본서는 Udemy Mumshad 강의이며, 대부분의 글이 공통으로 추천함 (11편 중 2025 이후 7편 이상).
2. killer.sh는 등록 시 2회 세션(36시간 사용)을 제공하며, 실제보다 어렵다는 평이 많음.
3. KillerCoda와 KodeKloud 실습 환경으로 연습한 사례가 있음. 개편 후 시나리오가 달라졌다는 지적도 있음.
4. 학습 기간은 처음 시작하면 2~3개월, 실무 경험이 있으면 약 1개월이 흔함.
5. 과제당 약 6분(2시간에 14~17개) 계산. 헷갈리는 문제는 넘기고 마지막에 돌아오기.
6. 명령형 kubectl과 `--dry-run=client -o yaml`로 뼈대를 만들고, 빠진 옵션만 공식 문서에서 찾기.
7. 별칭은 `alias k=kubectl`, `export do="--dry-run=client -o yaml"`, `alias now="--force --grace-period=0"` 정도가 공통(2024 글 중심).
8. 복사와 붙여넣기는 Ctrl+Shift+C/V, 우클릭, Ctrl+Insert/Shift+Insert 중 환경에 맞는 것을 미리 확인.
9. 트러블슈팅(kubelet, journalctl, crictl, systemctl)이 자주 등장하고 비중이 높다고 평가됨.
10. 2025 이후 자주 나온 주제: Gateway API, Helm(Argo CD), NetworkPolicy, PV/PVC, sidecar, CNI, PriorityClass, HPA.
11. etcd 백업/복원과 kubeadm 업그레이드는 출제 여부에 대해 글마다 의견이 다름.
12. 가장 큰 함정: 잘못된 노드에서 작업, 문제 첫 줄의 컨텍스트 전환 누락, 조건(do-not) 누락.
13. 환경 점검에 20~40분 걸리므로 30분 일찍 접속하고, 브라우저와 기기 문제를 미리 확인.
14. 응시권은 1년 안에 쓰고, 재응시 1회가 포함됨. 할인 시기(블랙프라이데이) 구매가 흔함.
15. 2025년 2월 개편 이후 난이도가 높아졌다는 평이 많으며, 개편 전 기출 중심 준비는 주의가 필요함.
